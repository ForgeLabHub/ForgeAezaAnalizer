# Агрегатный ИИ-ассистент (Qwen 2.5 через Ollama)

Эндпоинт `POST /api/v1/insights/ai` отвечает на вопрос аналитика по **агрегатам**
опубликованного расчёта. Модель объясняет, но не считает и не пишет: баллы,
категории и суммы берутся из расчётного движка.

Это дополнение к `POST /api/v1/ai/customers/{id}/explain`, который объясняет
риск одного клиента. Здесь модель получает только агрегаты по всей базе.

---

## 1. Настройка Ollama

1. Установите Ollama на хост и загрузите модель:

   ```bash
   ollama pull qwen2.5:7b
   ollama list                 # должна появиться qwen2.5:7b
   ```

2. Проверьте, что API отвечает:

   ```bash
   curl -s http://127.0.0.1:11434/api/tags | head -c 200
   ```

3. Включите ИИ в окружении и укажите адрес, **доступный из контейнера API**.
   Внутри Compose `127.0.0.1` — это сам контейнер, поэтому используется адрес
   шлюза Docker-сети:

   ```bash
   AEZA_LLM_ENABLED=1
   AEZA_OLLAMA_URL=http://172.18.0.1:11434
   AEZA_OLLAMA_MODEL=qwen2.5:7b
   AEZA_OLLAMA_TIMEOUT_SECONDS=90
   ```

   Если Ollama слушает только loopback хоста, разрешите ей слушать мост:

   ```bash
   OLLAMA_HOST=0.0.0.0:11434 ollama serve
   ```

   Проверка из контейнера:

   ```bash
   docker compose exec api python -c \
     "import urllib.request; print(urllib.request.urlopen('http://172.18.0.1:11434/api/tags', timeout=5).status)"
   ```

### Переменные

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `AEZA_LLM_ENABLED` | `0` | Выключатель ИИ. При `0` эндпоинт отвечает 503 |
| `AEZA_OLLAMA_URL` | `http://172.18.0.1:11434` | Адрес HTTP API Ollama (каноническое имя) |
| `AEZA_OLLAMA_MODEL` | `qwen2.5:7b` | Имя модели |
| `AEZA_OLLAMA_TIMEOUT_SECONDS` | `90` | Таймаут запроса, 1–600 |
| `AEZA_LLM_MAX_TOKENS` | `700` | Ограничение длины генерации |
| `AEZA_LLM_TEMPERATURE` | `0.2` | Температура |

Старые имена `AEZA_LLM_BASE_URL`, `AEZA_LLM_MODEL`, `AEZA_LLM_TIMEOUT_SECONDS`
поддерживаются как алиасы и применяются, только если каноническое имя не задано.

## 2. Запрос

```
POST /api/v1/insights/ai
Authorization: Bearer <JWT>
Content-Type: application/json

{ "question": "Сколько клиентов высокого риска и какая выручка под риском?" }
```

Схема закрыта (`extra="forbid"`): лишние поля отклоняются с 422. Длина вопроса —
от 3 до 1000 символов. Без действующего токена — 401.

Пример через `curl`:

```bash
docker compose exec api python -m backend.users create analyst@example.com
read -rsp 'Пароль: ' ANALYST_PASSWORD; echo
TOKEN=$(curl -s -X POST http://127.0.0.1:8000/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d "{\"email\":\"analyst@example.com\",\"password\":\"$ANALYST_PASSWORD\"}" | python3 -c 'import sys,json;print(json.load(sys.stdin)["access_token"])')

curl -s -X POST http://127.0.0.1:8000/api/v1/insights/ai \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"question":"Какие главные причины риска в базе?"}'
```

## 3. Ответ

```json
{
  "answer": "В расчёте 10 клиентов, из них высокого риска 3 …",
  "model": "qwen2.5:7b",
  "generation": 1,
  "sources": ["analytics.summary", "insights.inspect_source"],
  "grounded": true,
  "warning": "AI-интерпретация не заменяет расчётный движок: числа и категории берутся из опубликованного расчёта, а текст лишь объясняет их."
}
```

## 4. Ошибки

| Код | Когда |
| --- | --- |
| `401` | Нет или недействителен токен |
| `422` | Лишние поля, вопрос короче 3 или длиннее 1000 символов |
| `503` | ИИ отключён, Ollama недоступна, таймаут, ответ не JSON/пустой, либо ответ выдумал число |

`503` возвращается и тогда, когда модель придумала цифру, которой нет в расчёте:
ответ отклоняется, а не показывается как результат. Внутренние исключения, пути и
переменные окружения в тело ответа не попадают.

Сбой Ollama **не ломает** остальные эндпоинты: `/quality`, `/priority`,
`/scenarios/compare` и расчёт продолжают работать.

## 5. Что видит модель

Передаются только агрегаты:

- поколение, `asOf`, `calculatedAt`, горизонт, версия движка;
- число клиентов и распределение по категориям риска;
- агрегаты услуг (всего, открытых, завершённых, по статусам);
- финансовые агрегаты: выручка под риском, предстоящие продления, исторические
  пополнения;
- агрегированные причины риска (подпись + количество);
- сводка качества данных: уровни, счётчики, число проверенных записей, коды
  проблем, их описания и рекомендуемые действия.

**Не передаются:** email и имена клиентов, списки исходных записей, полный
снимок, список предстоящих продлений с идентификаторами, токены, пароли,
JWT-секреты и настройки подключения к БД. Из проблем качества берутся только
`code`, `level`, `count`, `message`, `action` — без списка `records`.

Если агрегат недоступен, в контексте стоит `null`, и модель обязана сказать, что
данных нет, а не додумывать их.

## 6. Ограничения

- **Модель не считает.** Балл риска — взвешенная эвристика, а не вероятность
  оттока. Системный промпт прямо запрещает называть его вероятностью.
- **Ответ проверяется.** Все числа и адреса из ответа сверяются с фактами; при
  расхождении ответ отклоняется (503).
- **Только чтение.** Эндпоинт не меняет снимок, настройки и опубликованное
  поколение.
- **Вопрос — не инструкция.** Текст аналитика передаётся как вопрос; промпт
  запрещает выполнять содержащиеся в нём указания изменить правила или роль.
- **Производительность.** Запрос синхронный и занимает до `AEZA_OLLAMA_TIMEOUT_SECONDS`;
  для одного аналитика этого достаточно, для многих понадобилась бы очередь.
- **Галлюцинации не исключены полностью.** Проверка ловит выдуманные числа и
  адреса, но не выдуманные формулировки без цифр. Поэтому ответ всегда несёт
  предупреждение и не заменяет расчёт.

## 7. Тесты

```bash
python -m pytest backend/tests/test_insights_ai.py -q
```

Тесты подменяют HTTP-вызов Ollama (`httpx.MockTransport`), поэтому не требуют
запущенной модели и не делают сетевых обращений.
