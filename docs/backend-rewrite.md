# Переписывание backend

Объём: корневое ядро, хранение, импорт, авторизация, HTTP API и эксплуатация.
Аналитику и risk-engine делает другой разработчик. Папка `backend/app/domain/`,
её тесты и прежний `api/serializers.py` не изменены и не подключены к новому runtime.
Самостоятельный модуль `backend/auth/`, `backend/main.py`, `backend/config.py`,
`db/`, фронтенд и исходный датасет также сохранены.

Новые библиотеки не добавлены. Использованы уже заявленные FastAPI, Pydantic,
SQLAlchemy, python-jose, PostgreSQL/SQLite и prometheus-client.

## Выполненные этапы

1. `core.py`: контракты CalculationModule/StorageModule, координация версий,
   повтор расчёта при конфликте, атомарная публикация.
2. `backend/app/db.py`, `storage.py`: неизменяемые снимки, настройки и результаты;
   SQL-фильтрация, сортировка с постоянным порядком ID при равенстве, пагинация.
3. `modules.py`: контракт внешней аналитики, проверка ответа, заглушка 503.
   Формулы, коэффициенты, признаки, платёжный календарь и агрегаты здесь не реализованы.
4. FastAPI: существующие пути React, типизированные ответы, защищённые маршруты,
   серверные сессии с отзывом при logout, единые ошибки.
5. SSE, таймер для текущего времени, метрики сохранённой версии, Docker и OpenAPI.
6. Тесты контракта, rollback, конкурирующих обновлений, перезапуска и отзыва сессий.

## Запуск из корня репозитория

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r backend/requirements.txt
.venv\Scripts\python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

Без внешнего модуля доступны вход и Swagger; /ready и действия, требующие
расчёта, возвращают 503. Демо-вход: analyst@aeza.test / demo123.
В общей среде задайте AEZA_ALLOW_DEV_SECRET=0, AEZA_JWT_SECRET и AEZA_ADMIN_PASSWORD.

```powershell
.venv\Scripts\python -m pytest backend/tests -q
.venv\Scripts\python backend/scripts/export_openapi.py
.venv\Scripts\python backend/scripts/load_snapshot.py dataset/data.json
docker compose up --build
```

Импорт требует подключённой аналитики: без неё возвращает код выхода 2.
Compose хранит PostgreSQL в `db/postgres/`, а пользователей и сессии — в
`db/auth.sqlite3`. SQL seed применяется PostgreSQL только при первом создании
каталога данных. Схема analyzer_* создаётся приложением; старые таблицы не
удаляются и автоматически не мигрируют. Для импорта нового снимка используй CLI.
Сохранённые версии не очищаются автоматически.

## Подключение внешнего модуля

Фабрика без аргументов задаётся в окружении:

```text
AEZA_ANALYTICS_FACTORY=my_analytics.integration:create
```

Для непосредственного подключения в Python: `create_app(settings, analytics=module)`.
Импортируется только явно заданный путь; автоматического поиска и подмены модулей нет.

Контракт определён в `backend/app/modules.py`:

```python
class AnalyticsModule(Protocol):
    def definition(self) -> ModelDefinition: ...
    def validate_settings(self, settings: dict) -> dict: ...
    def calculate(self, state: State) -> Analysis: ...
```

`ModelDefinition` содержит версию модуля, defaults и factors. Структура defaults:
horizonDays, weights, lowMax, mediumMax. Формат описаний факторов — FactorInfo из
`backend/app/api/schemas.py`. Набор ключей weights совпадает с набором факторов.
Значения по умолчанию и перечень факторов определяет внешний модуль.

`validate_settings` проверяет ограничения модели и возвращает полный словарь.
Неприемлемые настройки: ValueError/InvalidInput → HTTP 422.
Недоступность: NotReadyError → 503. Ошибка реализации → 500 с нейтральным ответом.

`State` определён в `core.py`: source, settings, generation, source_version,
model_version, captured_at, as_of, calculated_at. Входы считаются неизменяемыми.
source — словарь accounts/services/transactions, исходные camelCase имена полей.
Источник проверяется структурно, идентификаторы и связи обязательны; неизвестные
аналитические поля передаются как null. Интерпретация статусов, временных
противоречий и неполных данных принадлежит внешнему модулю.

`calculate` возвращает `Analysis(summary, customers)`. summary соответствует
Summary, customers — полным CustomerDetail из `api/schemas.py` и OpenAPI.
Дополнительные поля сохраняются. Все аккаунты и услуги источника должны быть
представлены; ID, владельцы, email и денежные поля аккаунта должны совпадать с
источником. Значения денег передаются парой {cents, eur}; cents — целое число,
eur — точная строка с двумя знаками. Неизвестные значения — пара null/null.
При нарушении контракта результат не публикуется, API возвращает 502.

Ядро добавляет собственную metadata, а адаптер сохраняет описание модели вместе
с результатом. После перезапуска без подключённого модуля сохранённые результаты
и настройки доступны для чтения; новые изменения, требующие расчёта, дают 503.
Версию definition.version нужно менять при изменении алгоритма: это вызывает
пересчёт после запуска, даже при неизменных входных данных.

## Согласованность и HTTP

Изменение проходит в порядке: валидация → чтение актуальной версии → расчёт →
compare-and-swap публикация одной транзакцией. Версии источника и настроек
увеличиваются только при их изменении; generation — при публикации расчёта.
Ошибка расчёта/записи оставляет прежние входы и результат.

При конкурентном обновлении ядро повторяет расчёт на свежих входах до трёх раз.
Неактуальный expectedGeneration даёт 409. Для PATCH он передаётся в JSON,
для импорта и reset — в query. Повтор идентичного импорта при фиксированном
времени не создаёт новую версию. GET-запросы ничего не пересчитывают.

Сводка, список, карточка, настройки и сведения об источнике возвращают generation,
sourceVersion, modelVersion, capturedAt, asOf, calculatedAt и заголовок
X-Analysis-Generation. Параметр `?generation=N` закрепляет одну версию для
нескольких запросов. Неизвестная версия — 404. Неизвестные параметры сортировки
и фильтров — 422. Прежние пути и обязательные поля React сохранены.

`GET /api/v1/analytics/events` — защищённый SSE с Bearer-токеном. Событие
analysis.updated содержит последнюю generation и metadata. Поддерживается
Last-Event-ID, после разрыва клиент запрашивает актуальные ресурсы этой версии.
Сервер не воспроизводит каждое пропущенное событие. Авторизация перепроверяется
во время подключения; отозванная/истёкшая сессия завершает поток. Для браузера
нужен fetch streaming с Authorization: обычный EventSource не задаёт этот заголовок.
Подключение SSE в React остаётся отдельной задачей.

При AEZA_AS_OF=now таймер запускает пересчёт раз в AEZA_RECALCULATE_SECONDS
(по умолчанию 60). При фиксированном времени таймер выключен. В нескольких
процессах CAS защищает публикацию, но таймер есть у каждого процесса; для первого
запуска рекомендуется один worker.

`GET /metrics` читает одну сохранённую generation непосредственно при сборе,
без предварительного обращения к сводке. Бизнес-агрегаты приходят из внешнего
модуля, API не рассчитывает риск. Персональных меток нет. Для Prometheus
задаётся отдельный AEZA_METRICS_TOKEN; без него нужна обычная сессия аналитика.

`GET /api/v1/source/observations` показывает наблюдаемые изменения статусов.
observedAt не объявляется временем события. Исчезновение из снимка отмечается
status=null и не превращается в deleted.

Swagger: /api/v1/docs. OpenAPI: /api/v1/openapi.json и `backend/openapi.json`.
Экспорт спецификации не требует запущенной БД или аналитики.

## Проверка

В backend/tests модуль FixtureAnalytics возвращает тестовые ответы API без
реализации аналитики. Он используется только в тестах. Тесты проверяют хранение,
доступ, контракт, конфликты, SSE и таймер; они не подтверждают корректность
будущего risk-engine. Его бизнес-сценарии проверяет владелец расчётного модуля.

Результаты проверки 23.10.2026:

- `python -m pytest backend/tests tests/test_auth.py -q`: 128 passed.
- TypeScript: проверка прошла; Vite: production-сборка прошла с исходной конфигурацией,
  загруженной через Node API (обход ограничения доступа esbuild к родительским каталогам).
- OpenAPI экспортирован, в том числе без установленной внешней аналитики.
- DDL десяти таблиц скомпилирован для PostgreSQL; транзакционные тесты выполнены на SQLite.
- Docker/Compose и живой PostgreSQL не запускались: Docker недоступен в окружении.

> импортируется; полный корневой набор собирается и проходит (**69 passed**),
