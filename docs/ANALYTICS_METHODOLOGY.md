# Методология оценки риска

## Формула

```
risk_score = 100 × Σ(wᵢ · fᵢ) / Σ(wᵢ)
```

где `fᵢ ∈ [0,1]` — нормализованный признак, `wᵢ` — его вес.

Это **объяснимая взвешенная модель признаков, а не обученная ML-модель**.
В датасете 10 аккаунтов и 30 услуг — недостаточно размеченных данных об
оттоке, чтобы обучать и валидировать статистическую модель. Никакой
«обученной модели» в проекте нет и не заявляется.

## Факторы

| Ключ | Вес по умолчанию | Значение 0 | Значение 1 |
|---|---:|---|---|
| `expiry_proximity` | 1.0 | окончание за горизонтом | услуга уже истекла |
| `autoprolong_off` | 0.8 | автопродление включено | выключено |
| `insufficient_balance` | 1.0 | `withdrawBalance ≥ price` | `withdrawBalance = 0` при `price > 0` |
| `failed_renewals` | 0.6 | 0 неудач | ≥ 2 неудач (`prolong` + `not_performed`) |
| `status_risk` | 0.9 | `active` | `blocked` |

Формулы признаков:

```
expiry_proximity     = clamp(1 − (expiresAt − reference)/horizon)
autoprolong_off      = 1 if not autoProlong else 0
insufficient_balance = 0                          if withdrawBalance ≥ price
                       0                          if price == 0
                       clamp(1 − withdrawBalance/price)  иначе
failed_renewals      = clamp(failed_count / 2)
status_risk          = {active: 0, prolong_wait: 0.6, suspended: 0.9, blocked: 1.0}
```

Горизонт по умолчанию — 30 дней, настраивается (`horizon_days`).

## Уровни риска

| Уровень | Диапазон |
|---|---|
| низкий | 0–34 |
| средний | 35–64 |
| высокий | 65–100 |
| `churned` | нет живых услуг, но есть `deleted` |
| `unknown` | нет услуг вообще — нечем оценивать |

Полосы не имеют дыр: дробные значения в промежутке (например 34.9) попадают
в нижнюю полосу, потому что сравнение идёт по нижней границе. Округление
применяется только при выводе, не при классификации.

## Неизвестные значения

Если данных для фактора нет (`withdrawBalance = None`), фактор получает
`value = None` и **исключается и из числителя, и из знаменателя**:

```
score      = 100 × Σ(wᵢfᵢ для известных) / Σ(wᵢ для известных)
confidence = Σ(wᵢ для известных) / Σ(все wᵢ)
```

Почему так, а не «неизвестное = 0»: если оставить вес в знаменателе с нулевым
вкладом, отсутствие данных **снижало** бы риск. Модель должна говорить
«не знаю» (`confidence < 1`), а не «всё хорошо».

Если известных факторов нет вообще (`Σ известных весов = 0`) — возвращается
уровень `unknown` и `confidence = 0`, деления на ноль не происходит.

## Риск клиента

Клиентский риск — это риск **худшей живой услуги**: клиент уходит тогда, когда
уходит его услуга.

- услуги со статусом `deleted` исключены из прогноза (это прошлое);
- если живых услуг нет, но есть `deleted` → уровень `churned` (уже ушли);
- если услуг нет вообще → `unknown`;
- денежная экспозиция считается **отдельно** и не влияет на `risk_score`.

## Настройка весов

Веса хранятся в таблице `risk_weights` и меняются через `PUT /api/weights`.

Валидация (`validate_weights`):

- неизвестные ключи → ошибка 400;
- нечисловые значения → ошибка;
- отрицательные → ошибка;
- сумма всех весов ≤ 0 → ошибка (иначе модель не определена).

Изменение весов немедленно влияет на `/api/customers`, `/api/services` и
`/api/dashboard`. Сброс — `POST /api/weights/reset`.

## Пример

Услуга: истекает через 15 дней (горизонт 30), автопродление выключено,
`withdrawBalance` покрывает цену, 1 неудачное продление, статус `blocked`:

```
f = [0.5, 1.0, 0.0, 0.5, 1.0]
w = [1.0, 0.8, 1.0, 0.6, 0.9]   Σw = 4.3
Σ(wᵢfᵢ) = 0.5 + 0.8 + 0 + 0.3 + 0.9 = 2.5
score = 100 × 2.5 / 4.3 ≈ 58.1  → средний риск
```

## Ограничения модели

- Веса заданы экспертно, а не подобраны на данных — это осознанный выбор.
- `failed_renewals` считается по `transactions`, где есть только `order` и
  `prolong`; полной истории пополнений нет.
- Модель не учитывает давность активности, кроме срока окончания услуги.
- Валидация на реальном оттоке невозможна: размеченных исходов нет.
