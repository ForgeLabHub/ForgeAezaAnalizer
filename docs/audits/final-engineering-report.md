## B. Архитектура

Канонический backend — `backend/app/` (FastAPI + SQLAlchemy). Он один собирается
в Docker-образ и один присутствует в OpenAPI стенда. Аналитический движок
подключается через `AEZA_ANALYTICS_FACTORY=backend.app.domain.module:create`.

```
nginx → SPA (React) + /api/, /health, /ready, /metrics → FastAPI
                                                         ├─ PostgreSQL (аналитика)
                                                         └─ SQLite (сессии)
```

Подробности, найденные дефекты и целевая структура — в
`docs/audits/architecture-audit.md`.

Слабые места: пересчёт всей базы на каждый запрос (A-7), `count(*)` на каждой
странице экспорта (A-8), нет ограничения попыток входа (A-9),
`AEZA_ALLOW_DEV_SECRET` по умолчанию `True` (A-10).

## C. Расчёты

Формула восстановлена из кода: `risk_score = 100 × Σ(wᵢ·fᵢ) / Σ(wᵢ)`,
суммируются только применимые факторы. Веса: `expiry_proximity` 3.0,
`prolong_wait_status` 2.5, `renewal_failure_rate` 2.5, `auto_prolong_disabled`
2.0, `insufficient_balance` 2.0, `suspended_status` 1.0, `failed_renewals` 0.0
(deprecated, чтобы не удваивать сигнал).

Деньги — целые евроценты, единственная конверсия на границе API, округление
`ROUND_HALF_UP` на `Decimal`. `withdrawBalance` исключён; бонус учитывается
только при `bonusState == "unlocked"`; неизвестное состояние бонуса трактуется
как недоступное.

`revenue_at_risk = price × score/100`, только для открытых услуг с ценой > 0
и `expiresAt` внутри горизонта; каждое продление один раз.

Контроль: 71.4 и 5.80 € воспроизведены. Подробности —
`docs/audits/calculation-audit.md`.

## F. Безопасность

Критических находок нет. Авторизация работает на всех приватных маршрутах,
пароли хешируются PBKDF2-HMAC-SHA256, JWT HS256 с зафиксированным алгоритмом,
CSV защищён от formula injection, `UnavailableAnalytics` возвращает 503, а не
нули.

Открытые риски: нет ограничения попыток входа (H-1), `AEZA_ALLOW_DEV_SECRET`
по умолчанию `True` (H-2), CORS `*` на стенде (M-1), нет заголовков
безопасности на хостовом nginx (M-3 — в контейнере исправлено). Подробности —
`docs/audits/security-audit.md`.

## Известные ограничения модели и данных

- Score — правиловой индекс, **не** вероятность оттока: исторических исходов
  в наборе нет, калибровка невозможна.
- `revenueAtRisk` — взвешенная стоимость продлений, **не** прогноз потерь.
- Официальный набор: 10 клиентов, 30 услуг, 100 транзакций. Расширенный seed
  добавляет 50 синтетических `demo-customer-*` (всего 60) — они не данные
  организатора и не должны выдаваться за реальных клиентов.
- `suspended` не означает отток; `deleted`/`blocked` — завершённые состояния.
- Причина удаления услуги в данных отсутствует и не додумывается.
