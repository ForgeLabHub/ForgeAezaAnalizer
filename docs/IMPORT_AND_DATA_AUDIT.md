## Источник

Единственный архив — `датасет.zip` в корне репозитория.

| Свойство | Значение |
|---|---|
| Размер (zip) | 14 983 Б |
| Распакованный размер | 82 151 Б |
| SHA-256 | `10af0815816e90e6cda8d84fe219a8696084c600d792acffa2317b876063c88f` |
| Вложенные архивы | нет |

Состав: `README.md`, `generate.py`, `test_generate.py`, `data.json`,
`001_schema.up.sql`, `001_schema.down.sql`, `002_seed.sql`.

Приложение читает **только `data.json`**. `generate.py` не исполняется.

## Безопасность распаковки

`importer/archive.py` отклоняет архив целиком при обнаружении:

| Проверка | Пример |
|---|---|
| path traversal | `../escape.txt` |
| абсолютный путь | `/etc/passwd` |
| путь с буквой диска | `C:\...` |
| не-regular член (symlink/device) | mode-биты в external attrs |
| дубликат имени | `a.txt` и `A.txt` |
| подозрительный коэффициент сжатия | > 200× при размере > 1 МиБ |
| превышение лимитов | > 5 000 членов или > 512 МиБ |
| повреждённый ZIP | не проходит `zipfile.is_zipfile` |

Вложенные архивы **не распаковываются автоматически** — только попадают в
отчёт (`nested_archives`).

## Валидация

Каждая запись проверяется до записи в БД:

- `id` — целое ≥ 1; `email` содержит `@`;
- денежные поля — целые ≥ 0;
- `bonusState` ∈ {locked, unlocked};
- `name` соответствует `^[A-Za-z0-9-]+$`;
- `paymentTerm`, `status`, `type` — из допустимых доменов;
- даты — строго `YYYY-MM-DDTHH:MM:SS.mmmZ`; наивные метки **отклоняются**;
- `expiresAt ≥ createdAt`;
- `0 ≤ amount ≤ 1000`;
- `not_performed` ⇒ `performedAt = NULL`; `performed` ⇒ `performedAt ≥ createdAt`;
- ссылочная целостность: `ownerId` → accounts, `serviceId` → services.

Отклонённые строки **перечисляются с причиной** в отчёте импорта. При
`strict=True` (по умолчанию) импорт прерывается целиком и БД не меняется.

## Атомарность и идемпотентность

- весь датасет пишется в **одной транзакции**;
- ошибка → rollback, частичного состояния не остаётся;
- повторный импорт **заменяет** таблицы → дубликатов нет;
- порядок удаления: `transactions → services → accounts` (RESTRICT);
- каждый запуск фиксируется в `import_runs` (sha256, счётчики, статус).

## Выявленные особенности данных

| # | Наблюдение | Оценка | Решение |
|---|---|---|---|
| 1 | **17 из 30 услуг истекли до снимка** | не дефект, но критично | исключены из будущих продлений; «уже истёк» = максимальная срочность для риска |
| 2 | `amount` не связан с `price` | смешение семантик | `amount` не конвертируется и не используется как деньги |
| 3 | нет полной истории пополнений | ограничение | `totalReplenished` берётся как есть |
| 4 | балансы не выводятся из транзакций | возможное расхождение | баланс и история не смешиваются |
| 5 | 6 услуг `deleted` | уже состоявшийся отток | уровень `churned`, вне прогноза |
| 6 | набор идеально сбалансирован (по 6 услуг каждого статуса) | синтетика | зафиксировано как ограничение |

Исходные данные **не изменялись**. Единственные преобразования — валидация,
нормализация дат в UTC и запись в одной транзакции. Затронуто 140 записей,
отклонено 0.
