# Модуль: движок аналитики и оценка риска

## 1. Назначение и границы
Считает риск продления услуги и выручку под риском на основе снимка данных. Работает
как чистое вычисление поверх домена (`backend/app/domain/*`, `core.py`).
Не делает: не получает данные из сети, не решает, что показать пользователю, не
хранит секреты. Риск — объяснимая эвристика, **не** вероятность оттока.

## 2. Сценарии использования
- Построение обзора: агрегаты по аккаунтам, услугам, выручке.
- Расчёт риска услуги с вкладом каждого фактора.
- Расчёт выручки под риском (цена ближайшего продления × оценка риска).
- Замена снимка и пересчёт: цифры меняются согласованно, провенанс обновляется.
- Отказ: домен недоступен → `UnavailableAnalytics`, API отвечает 503, а не пустотой.

## 3. Контракт
`/api/v1/analytics/*`, `/api/v1/customers/*` — в `backend/openapi.json`.
Внутренний контракт — `backend/app/domain/module.py` (`create()`), подменяемый через
`AEZA_ANALYTICS_FACTORY` (нужно для тестов и для альтернативных реализаций).

## 4. Данные
Владеет агрегатами и оценками; читает снимок (аккаунты, услуги, транзакции).
Деньги — `domain/money.py`, целые минорные единицы. Провенанс —
`domain/provenance.py`: каждая цифра знает свой источник.

## 5. Права
Чтение аналитики требует аутентификации (JWT из `backend/auth`); приём снимка
дополнительно требует `AEZA_SOURCE_INGEST_TOKEN`. Отказ — 401/403 без раскрытия данных.

## 6. Зависимости
Исходящие: только стандартная библиотека и собственный домен (сеть не используется).
Входящие: `backend/app/api/*`, AI-инструменты (`backend/app/ai/tools/analytics.py`).

## 7. Конфигурация
`AEZA_AS_OF` (фиксированная дата расчёта), `AEZA_ANALYTICS_FACTORY`,
`AEZA_RECALCULATE_SECONDS`, `AEZA_SEED_DEMO_DATA`. Неверный `AEZA_ANALYTICS_FACTORY`
ломает старт с внятной ошибкой — это лучше тихой подмены расчётов.

## 8. Сборка и отладка
Отдельного бинарника нет. Локально:

```bash
python -m pytest backend/tests/test_domain.py backend/tests/test_api.py -q
```

## 9. Тесты
`backend/tests/test_domain.py` (правила и деньги), `test_api.py` (маршруты),
`test_independent_acceptance.py` (независимая проверка сценариев),
`test_actions.py`, `test_deck_values.py` (совпадение цифр в презентации и API).
Главная гарантия «оценка объяснима» — проверка вкладов факторов.

## 10. Наблюдаемость
Метрики задержек по маршрутам (`/metrics`), провенанс снимка, коды 503 при
недоступном домене. Оператору: сверить дату снимка и `AEZA_AS_OF`.

## 11. Ограничения и готовность
- Нет размеченных исходов → нет калибровки и ROC-метрик; риск нельзя называть
  вероятностью.
- Нет сравнения сценариев «до/после» в одном ответе.
- Готовность: цифры в API и в презентации совпадают (тест `test_deck_values.py`);
  замена снимка не ломает согласованность агрегатов.
