# Модуль: внешние интеграции (почта, Telegram, снимок)

## 1. Назначение и границы
Опциональные каналы: SMTP-почта, Telegram Mini App/бот, приём снимка от источника.
Каждый канал включается отдельно и не влияет на работу аналитики.
Не делает: не является обязательным путём получения данных и не блокирует старт.

## 2. Сценарии использования
- Отправка письма-отчёта (`integrations/email.py`).
- Вход в Mini App через подпись Telegram и одноразовый код.
- Приём нового снимка по токену.
- Отказ: канал не настроен → операция сообщает «не настроено», сервис работает.

## 3. Контракт
`/api/v1/email/*`, `/api/v1/telegram/*`, `PUT /api/v1/source/snapshot` — в
`backend/openapi.json`. Провайдеры Telegram — `telegram/providers.py`.

## 4. Данные
Собственных таблиц нет. Telegram-сессии и OTP — в памяти/кэше с TTL
(`AEZA_TELEGRAM_SESSION_TTL_SECONDS`, `AEZA_TELEGRAM_OTP_TTL_SECONDS`); это осознанное
решение: OTP не должен переживать рестарт.

## 5. Права
Снимок — `AEZA_SOURCE_INGEST_TOKEN` (сравнение с постоянным временем). Telegram —
проверка подписи и максимальный возраст данных (`AEZA_TELEGRAM_AUTH_MAX_AGE_SECONDS`),
ограничение попыток OTP. Почта — только аутентифицированные пользователи.

## 6. Зависимости
Исходящие: SMTP-сервер, Telegram Bot API. Внешние системы изолированы адаптерами,
поэтому замена провайдера не затрагивает домен.

## 7. Конфигурация
`AEZA_TELEGRAM_BOT_ENABLED`, `AEZA_TELEGRAM_BOT_TOKEN`, `AEZA_TELEGRAM_WEBHOOK_SECRET`,
`AEZA_TELEGRAM_WEBHOOK_URL`, `AEZA_TELEGRAM_MINI_APP_URL`, `AEZA_TELEGRAM_OTP_*`,
`AEZA_SOURCE_INGEST_TOKEN`, SMTP-параметры. Пустой токен = канал выключен.

## 8. Сборка и отладка
```bash
python -m pytest backend/tests/test_email.py -q
python -m pytest backend/tests -q -k telegram
```

## 9. Тесты
`test_email.py` (в том числе `aiosmtpd`-сценарии), Telegram-тесты в `backend/tests`,
`test_api.py` для маршрутов снимка. Проверяется отказ при отсутствии конфигурации.

## 10. Наблюдаемость
Ошибки канала логируются без секретов (проверяется `check_docs.py` на «секретоподобные»
примеры и кодом логирования). Оператору: проверить наличие токенов и доступность
внешнего сервиса.

## 11. Ограничения и готовность
- Состояние Telegram-сессий в памяти: при нескольких репликах потребуется общее
  хранилище (сейчас не поддерживается).
- Нет очереди повторной отправки писем.
- Готовность: любой канал можно выключить, и продукт остаётся работоспособным.
