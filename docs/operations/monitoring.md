# Наблюдаемость

| Сигнал | Где | Назначение |
| --- | --- | --- |
| `/health` | api | живость, используется HEALTHCHECK в образе |
| `/metrics` | api, требует `AEZA_METRICS_TOKEN` | задержки и коды по маршрутам (`backend/app/metrics.py`) |
| Структурные логи | stdout контейнера | разбор инцидента |
| Провенанс снимка | `domain/provenance.py` | понять, из каких данных получена цифра |
| Состояние модели | `/api/v1/model/*` | доступность LLM-провайдера |

## Минимальные алерты

1. `/health` не отвечает 2 минуты.
2. Доля 5xx выше 1% за 5 минут.
3. `/metrics` недоступен или токен не задан на проде.
4. Снимок не обновлялся дольше ожидаемого (`AEZA_SNAPSHOT_POLL_SECONDS`).
5. Ошибки LLM-провайдера при `AEZA_AI_ENABLED=1` — деградация функций, не отказ сервиса.

## Чего нет

- Нет распределённой трассировки: один сервис, но фоновые пересчёты
  (`AEZA_RECALCULATE_SECONDS`) не связаны с запросами.
- Нет SLO, зафиксированных числом.
- Нет алертов «из коробки» — метрики отдаются, правила задаёт эксплуатация.
