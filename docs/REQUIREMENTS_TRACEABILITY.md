# Соответствие требованиям (Requirements Traceability)

Матрица соответствия проекта требованиям. Источники требований перечислены
ниже; **официальное ТЗ кейса в репозитории отсутствует** — это зафиксировано
как ограничение, и его содержание не выдумывается.

## Источники требований

| ID источника | Что это | Где | Статус |
|---|---|---|---|
| S1 | README организатора (контракт данных, единицы, ограничения схемы) | `датасет/README.md` внутри `датасет.zip` | **найден, прочитан** |
| S2 | SQL-схема организатора (DDL, CHECK, FK) | `датасет/001_schema.up.sql` | **найден, прочитан** |
| S3 | Генератор данных организатора (семантика полей) | `датасет/generate.py` | **найден, прочитан** |
| S4 | Официальное ТЗ кейса Aéza (UMIRHack 2026) | — | **НЕ НАЙДЕНО** |
| S5 | Постановка задачи от заказчика в переписке | сообщение пользователя | **частично: только перечень требований без формального документа** |

> **Важно.** Соответствие S4 подтвердить невозможно: документ не предоставлен
> и не найден ни в репозитории, ни в файловой системе, ни в архиве. Требования
> S4 выведены из S5 (текст задачи) и S1–S3. Пункты, требующие официального ТЗ,
> помечены как «невозможно подтвердить» — см. раздел «Требует уточнения».

## Блокирующие проблемы

На момент завершения этапа блокирующих дефектов не выявлено: приложение
запускается, импортирует реальный датасет, API и UI работают, тесты проходят.
Открытый риск — отсутствие официального ТЗ (S4), из-за чего часть требований
имеет статус «требует уточнения», а не «выполнено».
