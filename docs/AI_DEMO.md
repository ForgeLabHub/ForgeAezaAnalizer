# AI demo plan (2–3 minutes)

Status: prepared, **not yet turned into slides**. The AI features are verified
locally (see `docs/audits/llm-integration-audit.md`); production does not have
them yet, and the real `qwen2.5:7b` was not exercised from the agent
environment. Do not present anything below as a production fact until the
deployment in §5 is done.

| Time | Screen | Say | What is proven |

## 3. Verified facts usable in slides

Confirmed by running the commands in `docs/TESTING.md` and
`docs/audits/llm-integration-audit.md`:

- Official organiser dataset: **10 accounts / 30 services / 100 transactions**,
  **synthetic** (generated by `dataset/generate.py`) — never call it real
  customer data.
- Control values: customer **#10 = 71.4** (high), `revenueAtRisk` **5.80 €**,
  `upcomingRenewals` **17.03 €**, categories **3 high / 3 medium / 4 not_applicable**.
- Weight `expiry_proximity` 3 → 9 gives **81.8** and **7.72 €**.
- Tests: **239 backend + 69 root = 308**, all passing; frontend build exit 0.
- AI layer: 25 dedicated tests; grounded 200 / ungrounded 502 / unavailable 503
  demonstrated over real HTTP against a stub provider.
- The risk score is `rule_based_weighted`, `calibrated: false`.

## 4. Claims that must NOT go into a presentation yet

1. **"ИИ работает в продакшене"** — false. The stand runs `origin/main` and has
   no `/api/v1/ai/*` routes.
2. **"Модель показала/подтвердила, что клиент уйдёт"** — the model has no
   predictive power here and never should be quoted that way.
3. **Any score, sum or factor not reproduced by the engine.** The decks were
   rebuilt so every slide figure comes from `docs/deck/values.py`, which runs the
   real engine; `backend/tests/test_deck_values.py` fails if a slide drifts.
   Still, quote only what the current engine returns (71.4 / 5.80 €), never the
   older 73,3 / 5,74 € values that survive only as history in the notes and in
   `aeza_*` companion files.
4. **"Точность модели N %"** — no churn labels exist, so accuracy is undefined.
5. **"Данные реальных клиентов"** — the dataset is synthetic.
6. **"ИИ сам решает, что делать"** — it only explains and suggests; it cannot
   change data, balances or settings.
7. **Answers from the stub** as if they came from `qwen2.5:7b`.
8. **"Роли/права пользователей"** — there is no RBAC; one analyst role exists.

## 5. Before the demo on a stand

1. Deploy the current branch (see `docs/audits/release-gate.md`).
2. Verify from inside the API container that Ollama is reachable:
   `docker compose exec api python -c "import urllib.request;
   print(urllib.request.urlopen('http://host.docker.internal:11434/api/tags',
   timeout=3).status)"`.
3. Set `AEZA_LLM_ENABLED=1` and the model name, redeploy, then run the browser
   script above once end to end.
4. Decide and state which dataset the audience sees: the Compose seed is
   **60/115/285**, not the official 10/30/100, so the numbers on screen differ
   from the control values.
5. Have a fallback: if the model is slow, leave `AEZA_LLM_ENABLED=0` and present
   the deterministic explanation — the card says plainly why the AI is off.
