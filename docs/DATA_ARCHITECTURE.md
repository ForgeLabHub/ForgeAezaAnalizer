# Архитектура данных

Приложение использует один аналитический стек: FastAPI, PostgreSQL и React.
Учётные записи и серверные сессии хранятся отдельно в SQLite.

## Источник

Снимок находится в `dataset/data.json`. Compose подключает каталог `dataset/`
в API-контейнер как `/app/dataset` и передаёт путь через `AEZA_SNAPSHOT_PATH`.
При старте на пустой базе снимок проверяется и загружается штатным импортёром.
Далее API проверяет файл с интервалом `AEZA_SNAPSHOT_POLL_SECONDS` (по умолчанию
2 секунды). Изменившийся JSON проходит ту же проверку и немедленный расчёт, что
и запрос к API. Невалидный или временно недоступный файл не меняет опубликованную
версию; проверка повторится после следующего изменения файла.

Входной JSON содержит массивы `accounts`, `services` и `transactions`.
`services.ownerId` ссылается на `accounts.id`, а `transactions.serviceId` — на
`services.id`. Значения денег в аккаунтах и `services.price` заданы в целых
евроцентах. `transactions.amount` независимо сгенерирован и в расчётах денег
не используется.

Данные синтетические. В снимке нет истории исходов оттока, поэтому оценка риска
является объяснимой эвристикой, а не откалиброванной вероятностью.

## Хранение

| Данные | Хранилище |
| --- | --- |
| Снимки, настройки модели, опубликованные расчёты и клиентские результаты | PostgreSQL (`pg_data`) |
| Пользователи, хеши паролей, сессии и ключ RS256 | SQLite (`auth_data`) |
| Исходный снимок | `dataset/data.json` в репозитории |

Схема аналитики создаётся приложением. Загрузка снимка проходит целиком в одной
операции: при ошибке валидации или записи предыдущая опубликованная версия
остаётся доступной. Повторная загрузка идентичного снимка не создаёт дублей.

## Поток расчёта

`PUT /api/v1/source/snapshot` проверяет весь JSON, публикует новую версию источника
и запускает расчёт. Сайт может передать секрет из `AEZA_SOURCE_INGEST_TOKEN` в
заголовке `X-Source-Token`; аналитическая авторизация по Bearer-токену сохраняется.
Токен предназначен для серверного вызова, его нельзя помещать в браузерный код.
`Core` связывает generation с версиями данных и настроек модели. API читает
опубликованный результат, а не частично обновляемые строки.

Входной JSON — полный снимок: записи, отсутствующие в новой версии, не остаются
в актуальном снимке. Повтор идентичного JSON не создаёт новую generation.

Для обновления файлом заменяйте `dataset/data.json` в каталоге хоста, подключённом
через `AEZA_SNAPSHOT_DIR` (по умолчанию `./dataset`). Безопаснее записать временный
файл рядом и затем атомарно заменить `data.json`, чтобы API не прочитал запись
посередине. Сайт также может сразу отправить полный JSON через `PUT` на
`/api/v1/source/snapshot` с заголовками `Content-Type: application/json` и
`X-Source-Token`. При успешном ответе новая generation уже опубликована.

Для факторов риска используется взвешенное среднее доступных нормализованных
сигналов. Неизвестные значения не превращаются в ноль. Риск и денежная
экспозиция считаются отдельно; цена услуги участвует только в выручке под риском.

Подробное поведение API и формул описано в [руководстве проекта](PROJECT_GUIDE.md).
