# Развёртывание

## Docker Compose

Production-подобный стенд собирается из корня репозитория:

```powershell
Copy-Item .env.example .env
docker compose up -d --build
```

Compose запускает PostgreSQL 16, API и nginx с SPA. API слушает порт `8000`, интерфейс — `8080`. Seed в `db/analytics_seed.sql` загружается при первом запуске на пустом PostgreSQL-хранилище. Изменение seed-файла не обновляет уже существующий том.

Обычная остановка:

```powershell
docker compose down
```

Она сохраняет данные. Удаление томов через `docker compose down -v` удалит PostgreSQL и локальную базу авторизации.

## Настройки перед публикацией

В `.env` задайте уникальные значения:

- `AEZA_JWT_SECRET` — случайный секрет подписи JWT;
- `AEZA_ADMIN_PASSWORD` — пароль начального администратора;
- `AEZA_ADMIN_EMAIL` — имя начального администратора;
- `AEZA_CORS_ORIGINS` — точный список origin интерфейса, разделённый запятыми;
- `AEZA_METRICS_TOKEN` — отдельный токен для Prometheus, если он нужен.

Compose устанавливает `AEZA_ALLOW_DEV_SECRET=0` и требует секрет и пароль. Значения `change-me`, демонстрационный пароль и широкий CORS нельзя оставлять для общего или публичного доступа. Храните `.env` вне Git.

Для HTTPS поставьте перед Compose reverse proxy с действующим сертификатом, ограничьте доступ к API и метрикам согласно своей схеме, настройте резервное копирование PostgreSQL и проверьте восстановление копии. Не публикуйте порт БД.

## Сохранность состояния

- PostgreSQL Compose хранится в локальном каталоге `db/postgres/`.
- SQLite с учётными записями и сессиями хранится в именованном томе `aeza_auth`.
- Оба хранилища входят в `.gitignore`; не очищайте их как build output.
- Seed SQL используется только при первичной инициализации пустого PostgreSQL-хранилища.
