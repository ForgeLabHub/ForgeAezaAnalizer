# Схема данных

Две базы (см. [architecture/system-context.md](../architecture/system-context.md)):

| База | Назначение | Где описана |
| --- | --- | --- |
| PostgreSQL | предметные данные и агрегаты аналитики | `db/schema.sql`, `backend/migrations/*.sql`, `backend/app/schema.py` |
| SQLite | учётные записи, сессии, ключи | `backend/auth_schema.sql` (`db/schema.sql` копируется в образ как auth-схема) |

## Владение данными

| Домен | Кто пишет | Кто читает |
| --- | --- | --- |
| Снимок источника (аккаунты, услуги, транзакции) | импорт снимка и `AEZA_SNAPSHOT_PATH` | домен аналитики |
| Агрегаты и метрики риска | домен аналитики (`backend/app/domain/*`) | API, экспорт, AI-инструменты |
| Инсайты AI | сервис AI (после проверки инструментов) | API, отчёты |
| Действия и сценарии | `domain/actions.py`, `domain/scenarios` через API | API, AI-инструменты |
| Пользователи и сессии | `backend/auth` (SQLite) | API |

## Правила

1. **Деньги — целые минорные единицы + валюта.** Арифметика — `backend/app/domain/money.py`;
   `float` в расчётах выручки запрещён.
2. **Провенанс обязателен.** Каждый агрегат знает, из какого снимка получен
   (`domain/provenance.py`) — иначе цифру нельзя объяснить.
3. **Оценка риска объяснима:** вклад каждого фактора сохраняется, а не только итог.
4. **Снимок заменяем целиком** (`PUT /api/v1/source/snapshot`): это операция
   переиндексации, а не частичный `UPDATE` произвольных строк.

## Проверка

- Применение схемы на пустой базе: `make compose-up` → старт api применяет
  `schema.ensure_schema()` (сверка колонок + реестр миграций).
- Повторный старт: реестр `schema_migrations` исключает повторное применение.
- Данные: `python backend/scripts/load_snapshot.py` и
  `backend/tests/test_api.py`.
