# Методология выручки под риском

## Формула

```
revenue_at_risk = eligible_renewal_amount × risk_score / 100
```

`eligible_renewal_amount` — сумма цен тех услуг клиента, продление которых
попадает в горизонт прогноза.

## Что считается будущим продлением

Услуга входит в `eligible`, если одновременно:

1. статус **не** `deleted` (удалённая услуга не продлевается);
2. услуга «живая» по модели риска;
3. `reference_at ≤ expiresAt ≤ reference_at + horizon`.

То есть окончание услуги лежит **в будущем** и **внутри горизонта**.

## Что исключено и почему

| Исключение | Причина |
|---|---|
| `expiresAt < reference_at` | продление уже состоялось — это не прогноз |
| статус `deleted` | услуга удалена, продления не будет |
| баланс клиента | выручка считается от цены услуги, не от баланса |
| `totalReplenished` | исторические пополнения — не будущая выручка |
| `bonusBalance` | бонусы — не денежная выручка |
| `transactions.amount` | генерируется независимо от `price`, не деньги |
| двойной счёт | одно продление на услугу — ровно один раз |

## reference_at

Момент снимка определяется **из данных**: максимум `createdAt` и `performedAt`
среди услуг и транзакций. Для набора это `2026-10-19T14:35:53Z` — совпадает с
опорной датой генератора организатора (`2026-10-19T15:00:00Z`) с точностью до
минут.

Почему не системные часы: иначе один и тот же датасет давал бы разные ответы в
разные дни, и результаты были бы невоспроизводимы.

## Почему показатель мал

На исходном датасете **17 из 30 услуг истекли до момента снимка**. Значит,
будущих продлений внутри 30-дневного горизонта мало. Отсюда небольшие числа:

```
eligible_renewal   = €17.03
revenue_at_risk    = €7.48   (при весах по умолчанию, горизонт 30 дней)
```

Это корректный результат, а не дефект. Если бы мы считали истёкшие продления
будущими, показатель был бы искусственно раздут. Именно поэтому правило
«`expiresAt < reference_at` не считается» закреплено тестом
`test_past_expiry_excluded_from_revenue`.

## Горизонт

`horizon_days` — параметр запроса (1–365, по умолчанию 30). Увеличение
горизонта расширяет множество `eligible`, что видно в тесте
`test_horizon_changes_eligible_renewals`.

## Денежные единицы

Внутри — целые евроценты. `revenue_at_risk_cents` — каноническое значение;
`revenue_at_risk_eur` добавляется на границе API делением на 100. Двойной
конвертации нет.

## Что показатель не означает

`revenue_at_risk` — **не** полная выручка компании и не прогноз потерь.
Это оценка денежной экспозиции: сколько выручки от продлений находится под
риском с учётом вероятностного скоринга. Клиент с высоким риском, но без
продлений внутри горизонта даёт нулевую экспозицию — и это правильно.

## Проверки

| Инвариант | Тест |
|---|---|
| одно продление не считается дважды | `test_revenue_at_risk_counts_each_renewal_once` |
| `deleted` не входит | `test_deleted_service_excluded_from_revenue` |
| истёкшее не входит | `test_past_expiry_excluded_from_revenue` |
| баланс не влияет | `test_balance_is_not_part_of_revenue_at_risk` |
| RAR ≤ eligible | `test_real_dataset_revenue_is_bounded` |
