# Стиль кода и линт

## Что проверяется и чем

| Инструмент | Версия | Конфигурация | Где запускается |
| --- | --- | --- | --- |
| ruff | `>=0.17,<0.18` (`requirements-dev.txt`) | `ruff.toml` | `make lint`, `make verify`, CI |
| pytest | `>=8` | `pytest.ini`/`pyproject.toml` | `make test-backend`, `make test-auth` |
| openapi | — | `backend/openapi.json` | `make openapi-check` |

Конфигурация линтера лежит в репозитории (`ruff.toml`), а не берётся по умолчанию:
результат не должен зависеть от версии ruff на машине разработчика.

## Почему набор правил узкий

`select = ["E9", "F"]` — синтаксис, неопределённые имена, неиспользуемые импорты и
переменные. Это то, что почти всегда указывает на настоящую ошибку. Строгие наборы
(`I`, `UP`, `BLE`, `ISC`, `SIM`, `PLW`) дают в этом коде сотни замечаний стиля: их
включение — отдельная задача с отдельным ревью, а не побочный эффект переезда.

Порядок ужесточения:

1. Взять один набор (например `I` — сортировка импортов).
2. `ruff check --select I --fix`, отдельный PR, прогон тестов.
3. `# noqa: <код>` с комментарием там, где поведение намеренное.
4. Только после зелёного CI добавлять набор в `select`.

## Команды

```bash
make lint        # ruff по всему репозиторию
make test-backend
make test-auth
make verify      # lint + docs-check + тесты + openapi-check
```

## Договорённости

- Новый код — с тестом; тест не требует сети и PostgreSQL, если проверяется домен.
- Деньги — только через `domain/money.py`, `float` в расчётах запрещён.
- Любая цифра в ответе API имеет провенанс (`domain/provenance.py`).
