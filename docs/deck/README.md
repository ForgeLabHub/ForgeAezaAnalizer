# Презентация для защиты · «Хакатон Осень 2026» (ДГТУ)

Здесь лежит генератор колоды `aeza_hackathon_osen_2026.pptx` (10 слайдов, 16:9)
и исходные скриншоты интерфейса.

## Зачем генератор, а не готовый файл

Готовый `.pptx` нельзя проверить глазами: непонятно, откуда взялась каждая
цифра. Поэтому колода **собирается кодом**: скрипт импортирует настоящие
доменные модули `backend/app/domain/{risk,revenue,schema}.py` и прогоняет их по
`dataset/data.json`. Ни одно число не вписано руками, поэтому презентация не
может разойтись с продуктом.

Если меняются веса, пороги или логика скоринга — колоду достаточно пересобрать.

## Пересборка

```bash
pip install -r requirements-dev.txt      # python-pptx
python3 docs/deck/build_deck.py
```

Скрипт сам находит корень репозитория по наличию `dataset/` и
`backend/app/domain/`, поэтому запускать его можно из любого места.

Скрипт печатает контрольные значения — их удобно сверить с интерфейсом:

```
revenue at risk: 5,74 € -> tuned: 7,48 €
upcoming: 17,03 € | topups: 22 240,73 €
customer 10: 73.3 -> 81.0
cats: {'medium': 4, 'not_applicable': 4, 'high': 2} -> {'medium': 3, 'not_applicable': 4, 'high': 3}
```

## Опорные величины

| Параметр | Значение | Где задано |
| --- | --- | --- |
| Опорная дата (`AS_OF`) | 2026-10-19 15:00 UTC | `build_deck.py` |
| Горизонт прогноза | 30 дней | `build_deck.py` |
| Клиент для показа | `#10` | `build_deck.py` |
| Демонстрация веса | «Близость даты окончания», 3 → 9 | слайды 7–8 |

Опорная дата зафиксирована намеренно: без неё «дней до окончания» каждый день
разное, и числа на слайдах перестали бы воспроизводиться.

## Что нужно заполнить перед защитой

В колоде намеренно оставлены плейсхолдеры — этих данных в репозитории нет, и
выдумывать их нельзя:

- `[НАЗВАНИЕ КОМАНДЫ]` — слайд 1;
- имена и роли участников — слайды 1, 10;
- `[АДРЕС СТЕНДА]` — слайд 10, только подтверждённая ссылка;
- три QR-кода — слайд 10 (сейчас рамки-заглушки, не фальшивые коды);
- контакт (`[КОНТАКТ / TELEGRAM]`) — слайд 10.

## Скриншоты

`shots/` — снимки реального интерфейса (дашборд, список клиентов, карточка
клиента, причины риска, настройки, панели метрик «до/после»). Плейсхолдеры не
используются: все изображения сняты с работающего приложения на данных кейса.

## PDF

`aeza_hackathon_osen_2026.pdf` в корне — резервная копия на случай, если на
машине защиты нет шрифта Inter. PDF содержит встроенные шрифты, поэтому
отображается одинаково везде.
