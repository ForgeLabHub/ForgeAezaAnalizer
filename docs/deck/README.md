# Презентации для защиты · UMIRHACK 2026 и «Хакатон Осень 2026» (ДГТУ)

Здесь лежит один генератор на две защиты:

* `aeza_umirhack_defense.pptx` — UMIRHACK 2026, кейс Aéza;
* `aeza_hackathon_osen_2026.pptx` — «Хакатон Осень 2026», ДГТУ.

Обе колоды — 10 слайдов, 16:9, собраны из одного скрипта и отличаются только
строкой мероприятия на обложке. Скриншоты интерфейса лежат в `shots/`.

## Зачем генератор, а не готовый файл

Готовый `.pptx` нельзя проверить глазами: непонятно, откуда взялась каждая
цифра. Поэтому колода **собирается кодом**: скрипт импортирует настоящие
доменные модули `backend/app/domain/{risk,revenue,schema}.py` и прогоняет их по
`dataset/data.json`. Ни одно число не вписано руками, поэтому презентация не
может разойтись с продуктом.

Если меняются веса, пороги или логика скоринга — колоду достаточно пересобрать.

## Пересборка

```bash
pip install -r requirements-dev.txt      # python-pptx, pillow
python3 docs/deck/build_deck.py umirhack    # → aeza_umirhack_defense.pptx
python3 docs/deck/build_deck.py hackathon   # → aeza_hackathon_osen_2026.pptx
python3 docs/deck/build_deck.py both        # оба файла
```

Колода собирается в **фирменном стиле Aéza**: шрифт Manrope (заголовки, текст,
подписи) и палитра приложения — почти чёрный `#131313`, оранжевый
`#FF6B00`, светло-серый `#F4F4F4`. На обложке и финальном слайде стоит логотип
Aéza, собранный из официальных SVG (`brand/`).

Скрипт сам находит корень репозитория по наличию `dataset/` и
`backend/app/domain/`, поэтому запускать его можно из любого места.

Скрипт печатает контрольные значения — их удобно сверить с интерфейсом:

```
weight sum: 13.0
revenue at risk: 5,80 € -> tuned (expiry_proximity 9.0): 7,72 €
upcoming: 17,03 € | topups: 22 240,73 €
customer 10: 71,4 -> 81,8 | service-0030: 71,4 -> 81,8
```

## Откуда берутся числа

Все значения на слайдах считает `values.py`: он импортирует настоящий движок
(`backend/app/domain/module.py:create`) и прогоняет его по `dataset/data.json`
при `AS_OF = 2026-10-19 15:00 UTC`. Числа в `build_deck.py` не вписаны руками,
поэтому колода не может разойтись с продуктом. Скриншоты в `shots/` сняты с той
же конфигурации.

> **История.** Ранее числа были строками в `build_deck.py` и были сняты при
> прежнем весе `expiry_proximity = 15,0`, поэтому на слайдах стояли
> «73,3 / 100» и «5,74 €», тогда как продукт давал **71.4 / 100** и **5.80 €**.
> Скриншоты содержали те же старые числа. И текст, и скриншоты пересобраны под
> текущую конфигурацию, а расчёт вынесен в `values.py`, чтобы расхождение не
> повторилось. Подробности — `docs/audits/state-audit.md`.

Если меняются веса, пороги или логика скоринга — достаточно пересобрать колоду
и переснять скриншоты (`docs/deck/README.md`, раздел про `shots/`).

## Опорные величины

| Параметр | Значение | Где задано |
| --- | --- | --- |
| Опорная дата (`AS_OF`) | 2026-10-19 15:00 UTC | `build_deck.py` |
| Горизонт прогноза | 30 дней | `build_deck.py` |
| Клиент для показа | `#10` | `build_deck.py` |
| Демонстрация веса | «Близость даты окончания», 3 → 9 | слайды 7–8 |

Опорная дата зафиксирована намеренно: без неё «дней до окончания» каждый день
разное, и числа на слайдах перестали бы воспроизводиться.

## Что нужно заполнить перед защитой

В колоде намеренно оставлены плейсхолдеры — этих данных в репозитории нет, и
выдумывать их нельзя:

- `[НАЗВАНИЕ КОМАНДЫ]` — слайд 1;
- имена и роли участников — слайды 1, 10;
- `[АДРЕС СТЕНДА]` — слайд 10, только подтверждённая ссылка;
- три QR-кода — слайд 10 (сейчас рамки-заглушки, не фальшивые коды);
- контакт (`[КОНТАКТ]`) — слайд 10.

## Скриншоты

`shots/` — снимки реального интерфейса (дашборд, список клиентов, карточка
клиента, причины риска, настройки, панели метрик «до/после»). Плейсхолдеры не
используются: все изображения сняты с работающего приложения на данных кейса.

## Проверка вёрстки

```bash
python3 docs/deck/validate.py aeza_umirhack_defense.pptx   # геометрия и переполнения
python3 docs/deck/qa_visual.py aeza_umirhack_defense.pptx  # читаемость и контраст
```

`validate.py` проверяет, что ни один блок не выходит за границы слайда и не
переполняет свой прямоугольник, `qa_visual.py` — эффективное разрешение каждого
скриншота на слайде (не ниже 110 px/дюйм) и контраст каждой пары «текст/фон»
(не ниже 4,5:1 для основного текста). Оба скрипта сейчас дают ноль замечаний.

## PDF

В корне репозитория рядом с каждой колодой лежит одноимённый PDF — резерв на
случай, если на машине защиты нет шрифта Manrope. Шрифты встроены в PDF, поэтому
он отображается одинаково везде. Пересобрать после правок:

```bash
soffice --headless --convert-to pdf aeza_umirhack_defense.pptx aeza_hackathon_osen_2026.pptx
```

PDF — только страховка для показа. Правки и заглушки вносятся в `.pptx`, после
чего PDF пересобирается.
