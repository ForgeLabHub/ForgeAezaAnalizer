Документ фиксирует **фактическое** состояние репозитория после изучения

Дата аудита: 2026-10-23.

## Что лежит в репозитории

На `origin/main` сосуществуют **две независимые реализации** одного кейса
плюс отдельный модуль авторизации:

| Реализация | Каталог | Стек | Тесты |
|---|---|---|---|
| **A** | `aeza_analyzer/` | Python-пакет, SQLAlchemy+SQLite, vanilla-JS SPA, CLI | 52 |
| **B** | `backend/app/` + `frontend/` | FastAPI, SQLAlchemy, React+TypeScript+Vite, Docker Compose | 108 |
| **C** | `backend/auth/` | JWT (RS256) + SQLite, OIDC-провайдер | 17 (в `tests/test_auth.py`) |

Реализации **не импортируют друг друга** и имеют собственные модели данных,
скоринг, API и фронтенд. Единого приложения нет — это два продукта в одном
репозитории.

## Сравнение по критериям ТЗ

Оценка по обязательным требованиям `ТЗ.pdf`.

| Требование ТЗ | A (`aeza_analyzer/`) | B (`backend/` + `frontend/`) |
|---|---|---|
| Веб-панель: score, уровень, причина | ✅ SPA, вкладка Dashboard/Customers | ✅ React, страницы Dashboard/Customers |
| Явно указывать отсутствие оценки | ✅ уровень `unknown` | ✅ категория `insufficient_data` |
| Топ клиентов: ID, email, баланс, пополнения, score | 🟡 сортировка по score/RAR/балансу/id | ✅ сортировка по всем обязательным полям |
| Сортировка в обе стороны | ✅ | ✅ |
| Настройка коэффициентов через панель | ✅ вкладка Model | ✅ страница Settings |
| Сохранение настроек после перезапуска | ✅ таблица `risk_weights` | ✅ `model_settings` в БД |
| Денежная оценка с объяснением | ✅ | ✅ (балансы + цены + риск) |
| Живое обновление без reload | 🟡 пересчёт по кнопке | ✅ |
| `GET /metrics` (Prometheus) | ❌ | ✅ `prometheus-client`, счётчики/гистограммы |
| Расширяемость (новый признак) | ✅ | ✅ факторы описаны метаданными |
| Docker Compose | ❌ | ✅ `docker-compose.yml` (db + api + web) |
| Аутентификация (логин/пароль) | ❌ | ✅ JWT + защита `/api/v1/*` |
| `/api/v1/*` контракт из ТЗ | ❌ свои пути `/api/*` | ✅ точное соответствие |
| `/api/v1/docs` (Swagger) | 🟡 `/docs` | ✅ `/api/v1/docs` |
| OpenAPI-спецификация | 🟡 генерируется | ✅ генерируется |

**Вывод:** реализация **B** соответствует ТЗ существенно полнее. Реализация
**A** проигрывает по обязательным пунктам (нет `/metrics`, Docker, авторизации,
контракта `/api/v1/*`), но содержит более строгий импортёр, полный набор
документации и независимые тесты.

## Сильные стороны каждой

### A — `aeza_analyzer/`

- самый строгий безопасный импорт ZIP (traversal, symlinks, ratio, дубликаты);
- атомарность + идемпотентность с журналом `import_runs`;
- подробная документация (12 документов) и 52 теста;
- `UTCDateTime` — корректная работа с часовыми поясами в SQLite;
- CLI: `import` / `audit` / `serve` + `run.sh`.

### B — `backend/app/` + `frontend/`

- полный контракт ТЗ: `/api/v1/auth|analytics|customers|model|source`;
- Prometheus-метрики с низкой кардинальностью;
- аутентификация реально защищает бизнес-API (проверено: 401 без токена);
- React/TypeScript SPA со сборкой без ошибок;
- Docker Compose с health-check и PostgreSQL;
- 7 факторов риска с метаданными и русскоязычными объяснениями;
- 108 тестов, включая интеграционные.

### C — `backend/auth/`

- RS256/JWKS, OIDC-провайдер для доверенного сайта;
- 17 тестов;
- документация сохранена в [`AUTH_MODULE.md`](AUTH_MODULE.md).

## Дубликаты и расхождения

| Аспект | A | B | Конфликт? |
|---|---|---|---|
| Единицы денег | евроценты, `*_eur` | евроценты, `{cents, eur}` | нет — оба верны |
| `amount` транзакции | не деньги | не деньги | нет |
| Формула риска | 5 факторов, веса 1.0/0.8/1.0/0.6/0.9 | 7 факторов, веса 3/2/2/2.5/2/2/1.5 | **разные модели** |
| Пороги | 0–34 / 35–64 / 65–100 | `lowMax=34`, `mediumMax=64` | нет — совпадают |
| Пути API | `/api/*` | `/api/v1/*` | **разные контракты** |
| Трактовка `deleted` | `churned` | `not_applicable` / `concluded` | семантически совпадают |

Ключевое расхождение — **разные формулы и пути API**. Это два независимых
продукта, а не варианты одной системы. Объединять их код нельзя без
переписывания; объединять следует **продуктовый сценарий**.
